# 剧本创作工坊两程九阶（SKILL.md）工业化逐步实施计划书

本计划书基于 [`剧本创作工坊_SKILL_LangGraph改造方案.md`](剧本创作工坊_SKILL_LangGraph改造方案.md) 与 [`SKILL.md`](SKILL.md)，为实现一个**完全可运行、可交付部署、无缝融入现有系统**的 AI 原创短剧工业化生产系统而制定。

本计划严格恪守：**“现有技术栈直接复用、现有数据库零破坏平滑兼容、每一步均具备明确的输入/输出契约与机器自验标准”**。后续执行可直接按本计划中的步骤无歧义逐步编码落地。

│   FastAPI + LangGraph 0.2+ (StateGraph / Send / Checkpointer)               │

│   统一模型调度层 (app.services.aiClient / app.agents.runtime)               │
└──────────────────────────────────────┬──────────────────────────────────────┘

┌──────────────────────────────────────▼──────────────────────────────────────┐

│   媒体文件存储: data/storage/projects/{drama_id}/                           │
│   Node 服务 (backend-node): Express 保持现状，继续为画布播放器与合片提供服务│
└─────────────────────────────────────────────────────────────────────────────┘

### 1. 技术栈选型与增补
- **核心工作流引擎**：`LangGraph`（已在 `python-backend` 环境就绪，利用 `StateGraph`、`interrupt_after`、`MemorySaver` 支持 HITL 审批挂起与断点唤醒）；
- **数据契约与验证**：`Pydantic V2`（扩展现有 `LeanDramaScriptState`，定义 `IndustrialDramaMasterState`）；
- **数据库访问与会话**：`SQLAlchemy 2.0`（沿用 `session_scope` 与 `fetch_one` / `fetch_all`，保持轻量高效）；
- **事件流推送**：现有 `EventBus`（基于 `asyncio.Queue` 实现的 Server-Sent Events，向前端毫秒级广播节点进度与红蓝自审状态）；
- **外部模型通信**：现有 `aiClient.chat_complete`，支持流式与结构化 JSON 提取（`extract_first_json_payload`）；
- **音频时间轴与 SRT 工具**：新增轻量内置解析器（纯 Python 标准库 `re` + `datetime`），零引入重量级外部 C 依赖。

## 二、 数据库零破坏兼容策略 (Zero-Breaking Schema Policy)

为了**绝对不破坏现有数据库结构与已有短剧数据**，采用**“核心实体映射 + 柔性 JSON 字段扩展”**原则：

| `SKILL.md` 工业产物 | 映射的现有数据库表 | 存储字段与策略 | 兼容性保证 |
| :--- | :--- | :--- | :--- |
| **阶段 1：`01_bible.json`** | `dramas` | 存入 `dramas.metadata['bible_v2']` 与 `dramas.metadata['double_track_rules']` | 基础字段（title, genre, total_episodes）与表结构完全不变 |
| **阶段 2：`02_characters.json`** | `characters` | 存入 `characters.identity_anchors` 与 `metadata['psychological_quad']` | 复用原 `characters` 记录，新增字段均以 JSON 存入原有 TEXT 列 |
| **阶段 3：`03_environments_props.json`** | `scenes` & `props` | 存入 `scenes.metadata['weathering_layers']`、`props.metadata['action_states']` | 原空间/道具逻辑无影响，前端按需反序列化 |
| **阶段 4：`04_outline.json` & `04_audio_bible.json`** | `dramas` & `episodes` | 大纲存入 `episodes.metadata['task_card']`，音乐动机母库存入 `dramas.metadata['audio_bible']` | 与老版大纲字段并存，老数据自然降级 |
| **阶段 5：`episodes_screenplay/`** | `episodes` | 纯文学 JSON 存入 `episodes.script_content`（标准 JSON 字符串） | 下游直接根据 JSON 键值解析场景对白 |
| **阶段 6：`05_visual_audio_assets.json`** | `dramas` & `assets` | 全局注册表存入 `dramas.metadata['visual_audio_assets_registry']` | 记录 APPROVED 单项素材，同时在 assets 表建立真实文件索引 |
| **阶段 7：`storyboards/sb_XX.json`** | `storyboards` | 首尾帧/多图配置、口型动力学存入 `storyboards.metadata`，SRT 存入 `episodes.metadata['srt_export']` | 原有分镜列表字段完全兼容 |
| **阶段 8：`audio_mastering/`** | `episodes` | 混音调度、Ducking 避让参数与 BGM 提示词存入 `episodes.metadata['audio_mastering']` | 完全挂载在分集元数据中，无新增必填列 |
| **全局红蓝对抗报告** | `dramas` / `episodes` | 存入各级 `metadata['red_blue_audit']` | 前端审查卡片直接取用 |

## 四、 详细逐步实施计划

### 步骤 1：工业契约模型完善与数据持久化适配器 (Data Contracts & Adapters)

- **目标**：在不改动已有物理表的前提下，完成双程九阶所有实体对象与 SQLite/MySQL `metadata` JSON 的双向序列化适配器。
- **涉及文件**：
  - `python-backend/app/schemas/script_graph_state.py`
  - `python-backend/app/workflows/adapters/drama_storage_adapter.py` (新建)
  - `python-backend/tests/unit/test_drama_storage_adapter.py` (新建)
- **实现细节**：
  1. 在 `script_graph_state.py` 中补充校验器：
     - `EpisodeScriptV2`：校验包含 `safety_guardrails_lock`、`scenes`、`dramatic_rhythm_check`、`episode_end_physical_delta`；
     - `StoryboardShot`：校验 `generation_mode` 必须为 `first_last_frame` 或 `multi_image_reference`，校验首尾帧必填 `first_frame_prompt`/`last_frame_prompt`/`video_motion_prompt`，校验多图参考必填 `reference_assets`；
  2. 实现 `drama_storage_adapter.py`，提供 4 个原子落库与反序列化方法：
     - `persist_first_journey_state(db, drama_id, state)`：将阶段 1~5 成果安全写入 `dramas.metadata`、`characters`、`scenes`、`props`、`episodes`；
     - `load_first_journey_state(db, drama_id) -> IndustrialDramaMasterState`：从数据库重构第一程全局状态；
     - `persist_episode_visual_package(db, drama_id, episode_num, manifest, storyboards, srt_content, mastering)`：将阶段 6~8 成果写入对应分集与分镜表；
     - `load_episode_visual_package(db, drama_id, episode_num) -> dict`：读取单集视听工程包。
- **自测与验收标准**：
  - 运行单元测试：构造包含 12 集完整波次文学稿与单集首尾帧分镜的 State，执行 Save ➔ Load ➔ 比对，字段 100% 幂等恢复。

### 步骤 3：红蓝对抗 AI 质量自审 Agent 与 Blocking 自动重构路由 (Red-Blue Auditor)

- **目标**：实现独立的红蓝对抗审查 Agent，对阶段 1~8 的交付物进行对抗审查，实现阻断级缺陷就地重构、警示级建议呈报主创。
- **涉及文件**：
  - `python-backend/app/agents/red_blue_auditor.py` (新建)
  - `python-backend/app/workflows/routers/audit_router.py` (新建)
  - `python-backend/tests/unit/test_red_blue_auditor.py` (新建)
- **实现细节**：
  1. **审核 Agent 提示词设计**：
     - **蓝军指令**：客观硬指标核查（时间轴秒数累加是否严格等于总时长、禁令红线是否触发、格式是否合法）；
     - **红军指令**：魔鬼挑刺制片人（专门挑出：戏剧张力硬伤、台词说教、反派降智、AI 视频容易融化穿模的动作）；
  2. **风险判定与结构化输出**：
     - 输出必须符合 `RedBlueAuditReport`：包含 `verdict`（`GREEN_APPROVED` / `YELLOW_WARNING` / `RED_BLOCKING`）、`blocking_issues`、`warning_suggestions`；
  3. **条件路由与重试机制 (`audit_router.py`)**：
     - 若 `verdict == RED_BLOCKING` 且重试次数 `< 2`：提取 `blocking_issues` 作为修改指令，自动回流当前阶段重新生成；
     - 若重试次数达到上限，或判定为 `YELLOW_WARNING` / `GREEN_APPROVED`：放行至当前阶段的 HITL 门控，由创作者裁决。
- **自测与验收标准**：
  - 测试用例 1：故意注入含“亲子鉴定当场撕毁”禁令情节的文本，审查器必须判定为 `RED_BLOCKING` 并指明违反禁令条款；
  - 测试用例 2：注入合规文本，审查器给出蓝军全打勾、红军提 1~2 条 `YELLOW_WARNING` 审美建议并放行。

### 步骤 4：阶段 5 Mini-Arc 疾速波次剧本吞吐与 0 秒物理咬合调度 (Stage 5 Batching)

- **目标**：彻底消除单步低效拉扯，实现按 3~4 集戏剧小高潮单元连续吞吐标准文学剧本 JSON 数组，并实现单元内与波次间的集间 0 秒物理接力。
- **涉及文件**：
  - `python-backend/app/workflows/nodes/stage5_screenplay.py` (新建)
  - `python-backend/app/workflows/utils/physical_continuity.py` (新建)
  - `python-backend/tests/unit/test_stage5_mini_arc.py` (新建)
- **实现细节**：
  1. **波次批次计算器**：
     - 根据 `total_episodes`（如 12 集）与 `current_mini_arc_index`，自动计算当前批次集数范围（第 1 波：1-3集；第 2 波：4-6集……）；
  2. **事前三道安全护栏锁绑定**：
     - 在 Prompt 中对每集强制锁定：`subtext_matrix`（表面借口 vs 核心企图，3~5个禁词）、`friction_and_cost_preset`（肉体/利益代价与现实物理毛刺）、`detailed_causal_task`；
  3. **单元内与单元间 0 秒物理咬合 (`physical_continuity.py`)**：
     - 后一集第一秒必须无缝接力前一集集尾绝杀断点的物理快照：
       * `character_pose_pickup` 咬合前一集的 `character_pose`；
       * `held_prop_pickup` 咬合前一集的 `held_prop`；
       * `environment_pickup` 咬合前一集的 `environment_state`；
  4. **批次生成与合并**：
     - 调用模型一次性吐出当前波次的 3~4 集纯 JSON 数组，校验通过后存入 `completed_screenplays` 字典。
- **自测与验收标准**：
  - 运行单元测试：一次调用连续输出 3 集完整文学剧本 JSON，验证第 2 集开头的 `previous_episode_physical_pickup` 准确引用了第 1 集末尾的 `episode_end_physical_delta`。

### 步骤 5：第一程全季文学定稿门禁与状态冻结 (Literary Gatekeeper)

- **目标**：实现第一程文学总门控，全季剧本定稿前阻断下游一切视听开销，定稿后对全季文学剧本加锁并生成全息快照。
- **涉及文件**：
  - `python-backend/app/workflows/nodes/literary_gatekeeper.py` (新建)
  - `python-backend/tests/unit/test_literary_gatekeeper.py` (新建)
- **实现细节**：
  1. **波次完成检查器**：
     - 若 `len(completed_screenplays) < total_episodes`，状态机循环路由回 `stage5_screenplay` 处理下一波次；
     - 若全季剧本全部生成完毕，自动转移至 `first_journey_gatekeeper`；
  2. **声明式 HITL 中断**：
     - 配置 `interrupt_after=["first_journey_gatekeeper"]`；
     - 挂起状态机，向 SSE 总线广播 `FIRST_JOURNEY_REVIEW_NEEDED` 事件；
  3. **定稿锁定与解锁第二程**：
     - 收到创作者前端点击“确认全季文学定稿，解锁视听工程”后：
       * 置位 `literary_journey_locked = True`；
       * 更新数据库 `dramas.metadata['literary_locked'] = 1`；
       * 初始化第二程游标 `current_visual_episode = 1`；
       * 唤醒状态机，正式步入阶段 6。
- **自测与验收标准**：
  - 模拟状态机运行至阶段 5 完毕后被正确挂起，状态查询显示处于等待定稿审批中；传入 resume 指令后成功解锁并进入阶段 6。

- **实现细节**：
  1. **双模式黄金决策树**：
     - 镜头涉及物理形变、不可逆撕裂、剧烈扑倒或猛烈开合：强制判定为 `first_last_frame`，必须输出首帧 Prompt、尾帧 Prompt 与运动 Prompt，严禁用于细腻微表情；
     - 镜头涉及角色对白、微表情隐忍、过肩对峙：强制判定为 `multi_image_reference`，必须指定引用的 APPROVED 单项资产 ID 数组与多图提示词，严禁用于剧烈物理破坏；
  2. **全息声学与口型动力学注入**：
     - 对白/旁白：结合阶段 4 声纹基准与阶段 5 发声括注，注入带声纹 ID、腔体闭合指令与呼吸停顿的完整提示词；
     - 拟音 Foley：标注具体音效与 `+2dB ~ +3dB` 增益；
     - 口型动力学：显式标注下颌开度限制 `jaw_open_scale`（咬牙 0.4~0.5 vs 呼喊 0.8~0.9）、嘴角张力与头部微动；
  3. **SRT 自动导出 (`srt_generator.py`)**：
     - 依据镜头对白、语速与起止时间码，同步编译出符合标准播放器格式的 `.srt` 字符串。
- **自测与验收标准**：
  - 校验产出的镜头列表中，每个镜头的时长在 2.5~4.5 秒之间，总时长精确等于单集规划秒数；生成的 SRT 时间码与镜头时间码 100% 对齐。

### 步骤 8：第二程阶段 8 多轨智能音频工程与混音调度 (Stage 8 Audio Mastering)

- **目标**：依据阶段 7 绝对毫秒时间轴与阶段 4 音乐动机母库，动态编译分段 BGM Prompt，计算语音侧链避让 (Audio Ducking) 与断崖静音卡点，并输出 NLE 剪辑轨道指南。
- **涉及文件**：
  - `python-backend/app/workflows/nodes/stage8_audio_mastering.py` (新建)
  - `python-backend/app/workflows/utils/audio_scheduler.py` (新建)
  - `python-backend/tests/unit/test_stage8_audio_mastering.py` (新建)
- **实现细节**：
  1. **分段戏剧化 BGM Prompt 动态编译**：
     - 继承 `04_audio_bible.json` 中的 Leitmotif（如动机 A 准备钢琴+40Hz低频）；
     - 严格按照当前集时长（如 120s）分段编排：`[00:00-00:03]` 开场重击 ➔ `[00:03-00:45]` 低频暗流 ➔ `[00:45-00:48]` 核心反转断崖静音 ➔ `[00:48-01:58]` 爬坡对攻 ➔ `[01:58-02:00]` 绝杀断点 Sub-drop 随黑屏骤停；
  2. **动态侧链分贝避让 (Audio Ducking)**：
     - 读取 SRT 字幕时间区间，对白区 BGM 自动衰减至 `-18dB ~ -22dB`；纯动作悬疑区拉升至 `-10dB ~ -12dB`；
  3. **断崖式主观静音法则**：
     - 在第 45 秒微反转处强制设置 2~3 秒 `-inf dB` 绝对物理静音，消除音乐，留出拟音；
  4. **NLE 轨道指南与落库**：
     - 生成 Track A1(对白 -23 LUFS)、A2(拟音 +2dB)、A3(BGM + Ducking) 的剪映/Premiere 导入指导配置。
- **自测与验收标准**：
  - 运行单元测试：验证混音计划表中，包含至少一处持续 2~3 秒的 `-inf dB` 静音时间段，且对白时间段的 BGM 音量均低于 `-18dB`。
